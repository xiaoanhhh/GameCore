## 作用

提供客户端与游戏节点之间的 TCP/TLS 长连接。原理和完整流程见 [03-客户端与服务器网络通信](../../03-客户端与服务器网络通信/README.md)。

## 实际制品

全部为 4.2.19.Final，没有混用版本，也没有使用 `netty-all`。

| 制品 | 引入方式 | 职责 |
| --- | --- | --- |
| `netty-transport` | 直接 | Bootstrap、NIO Channel、EventLoop、ChannelGroup |
| `netty-codec-base` | 直接 | 长度帧、消息编解码基类 |
| `netty-handler` | 直接 | 读写超时、`SslHandler` |
| `netty-resolver-dns` | 直接 | 客户端异步 DNS 解析 |
| `netty-common` | 传递 | Future、线程工具，内嵌 [JCTools](../JCTools/使用说明.md) |
| `netty-buffer` | 传递 | ByteBuf、分配与引用计数 |
| `netty-resolver` | 传递 | 名称解析基础 |
| `netty-codec-dns` | 传递 | DNS 消息编解码 |
| `netty-transport-native-unix-common` | 传递 | `netty-handler` 带入；项目使用标准 NIO，没有启用 epoll 或 kqueue |

`netty-transport`、`netty-codec-base`、`netty-common`、`netty-buffer`、`netty-resolver` 的 JAR 摘要见 [artifact-sha256.csv](artifact-sha256.csv)。服务器发行包的完整运行库清单见 release.json。

## 调用位置

| 代码 | 使用的接口 |
| --- | --- |
| `network-transport/.../ProtocolPipeline` | `LengthFieldBasedFrameDecoder`、`LengthFieldPrepender`，4 字节长度帧 |
| `network-transport/.../IoResources` | 事件循环组的创建和优雅关闭 |
| `network-transport/.../AsyncOutbound` | 有界的可靠队列和最新快照发送 |
| `network-transport/.../TransportTls` | `SslContextBuilder`、`SslProvider.JDK`，TLS 1.3/1.2，5 秒握手，校验 CA 和主机名 |
| `network-transport/.../GameNetworkConnection` | 客户端连接；`DnsAddressResolverGroup` 异步解析 |
| `network-transport/.../experiment/SimulatedNetworkHandler` | `ChannelDuplexHandler`；开发用的延迟和丢包模拟，只在显式开发开关和回环连接上安装 |
| `client/.../network/GameNetworkClient` | Tank 专用端点的客户端连接 |
| `game-server/.../multigame/NettyMultiGameServer` | 多游戏服务器：`ServerBootstrap`、读写超时、限流、`DefaultChannelGroup` |
| `game-server/.../NettyGameServer` | Tank 专用端点的服务器 |

DNS 解析限制：最多 4 次查询，单次查询 1 秒超时，查询缓存 16 项，TTL 上限 60 秒。

## 线程约定

- EventLoop 上不运行游戏模拟，也不等待阻塞操作。
- 图形线程不等待网络 Future，Netty 回调也不操作 Stage。
- 所有入站 ByteBuf 由 Pipeline 基类释放。测试时开启 `io.netty.leakDetection.level=paranoid`。

## 分发与升级

客户端和服务器的发行包都附带完整的 Netty LICENSE、NOTICE、32 个组件许可以及 JCTools、Protobuf 的 LICENSE。

新增组件或升级版本时，要重新核实 BOM、实际运行依赖、内嵌代码的版本和许可，并重跑网络测试。本文不是法律意见，也不是漏洞扫描结论。跨平台和外部 DNS 环境没有专门验收。
