# OpenJDK / Temurin

项目在四个场景使用 Java 21 运行时，它们的来源和分发方式不同。

| 场景 | 发行版 | 是否随项目分发 |
| --- | --- | --- |
| 开发与构建 | 本机 Java 21 工具链 | 否 |
| Windows 便携包 | Temurin 21.0.13+9 Windows x64 裁剪运行时 | **是** |
| 云主机运行 | Ubuntu `openjdk-21-jre-headless` | 否，由系统包管理器安装 |
| 本机 Linux 验证 | Temurin 21.0.13+9 Linux x64 JDK | 否，只在 WSL 测试中使用 |

## Windows 便携包

- 使用 Temurin 的 `jpackage` 和 `jlink` 生成裁剪运行时和原生启动器，不把本机其他 JDK 复制给用户。
- 许可：GPL-2.0 with Classpath Exception，各组件以[随包原文](license/windows-temurin-21.0.13)为准。来源：[官方发行](https://adoptium.net/temurin/releases/)、[许可说明](https://adoptium.net/docs/faq)。
- JDK SHA-256：`a4dbaa05fca4bd89d84584e58c459bd732efebb1722af80ab13c6516832004f9`，已与 Adoptium 官方元数据核对。
- 对应源码来自发布记录中的 adoptium/jdk21u 提交 `2ab10ca20c19` 和 temurin-build 提交 `1cf43d7a3e77886bfea7d550a902e151a87d724d`，经 GitHub 官方 TLS 下载。来源、固定版本和校验信息见 [windows-temurin-21.0.13-source.json](windows-temurin-21.0.13-source.json)；其中源档的 SHA 是自行计算的，不是官方发布值。
- 两个完整源档和许可随便携 ZIP 放在 `third-party/OpenJDK/corresponding-source`，不是用将来提供源码的承诺代替。
- 模块列表见 [runtime-release.txt](license/windows-temurin-21.0.13/runtime-release.txt)。
- 开发 JDK 和源档只保存在 `.cache`，不提交二进制。

实际验证：包内 JVM 通过了 ECDH、Java HTTP、Netty、中文资源和全部六项图形任务，见阶段 11 验证记录。只在 Windows 11 x64 上实测过，其他电脑、显卡、ARM、Linux 和 macOS 没有验证。

包内运行时需要跟进安全补丁，不能长期冻结在这个版本。Classpath Exception 不决定 GameCore 自身的开源许可，也不影响素材的权属。

## 云主机运行时

| 项目 | 内容 |
| --- | --- |
| 软件包 | `openjdk-21-jre-headless:amd64` `21.0.12.1+1-1~22.04.4` |

## 本机 Linux 验证

WSL 中使用 Temurin 21.0.13+9 Linux x64 JDK 验证发行包，SHA-256 `d7f5d5cf865a2902b70ff549b97586a7d3f234e016f041ab447ea740c7d66d1c`，已与 [Adoptium API](https://api.adoptium.net/v3/assets/latest/21/hotspot?architecture=x64&image_type=jdk&os=linux) 核对。这个 JDK 不打包。

项目调用的 JDK 能力：JSSE（TLS）、`HttpServer`（健康检查）、MXBeans、JFR。没有新增加密算法或 JNI 依赖。
