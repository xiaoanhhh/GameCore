# Protocol Buffers

| 项目 | 内容 |
| --- | --- |
| 版本 | 运行库 `com.google.protobuf:protobuf-java:4.34.2`；编译器 `com.google.protobuf:protoc:4.34.2`（上游发布号 [v34.2](https://github.com/protocolbuffers/protobuf/releases/tag/v34.2)，Java 制品带 4 前缀） |
| 类型 | 客户端和游戏节点的运行依赖；`protoc` 只用于构建 |
| 许可 | BSD-3-Clause，原文见 [LICENSE](LICENSE)，含生成代码的归属说明 |
| 来源 | [官方仓库](https://github.com/protocolbuffers/protobuf/tree/v34.2)、[Maven Central](https://repo.maven.apache.org/maven2/com/google/protobuf/) |

## 作用

定义对局通道的消息格式。协议设计见 [01-通信分层与协议](../../03-客户端与服务器网络通信/01-通信分层与协议.md)。

## 调用位置

- `protocol/src/main/proto/` 下有 `games.proto`（多游戏端点）、`tank.proto`（Tank 专用端点）、`replay.proto`（录像）。生成代码在 `build` 目录，不手工维护。
- `protocol` 以 `api` 导出 `protobuf-java`。
- `game-online` 的编解码器、`network-transport`、`game-server`、`client` 调用 Builder、`parseFrom`、`CodedInputStream`，并校验字段和未知枚举。

Protobuf 只负责编解码。长度边界、权限、数值合法性和权威规则都由应用代码实现。项目没有使用 Java 原生对象序列化、动态 schema 或任意类反序列化。

`game-api` 和三个规则模块不依赖 Protobuf。

## 两个运行版本

客户端和游戏节点使用 4.34.2。平台服务由 Spring Boot 4.1.2 的官方 BOM 解析到运行库 4.36.2，用于读取比赛的最终快照，不生成另一套协议。两者在不同进程中，同一进程内只有一个版本。跨进程兼容性由真实 HTTP/TCP 集成测试和桌面联机验证，见阶段 10 验证记录。

## 限制

- `protobuf-java` 没有运行时传递依赖。`protoc` 不进入游戏分发，构建依赖见[插件说明](../Protobuf-Gradle-Plugin/使用说明.md)。
- 实际下载验证过的生成器是 Windows x86_64，其他系统由固定坐标选择 classifier，没有实际验证。

- 升级时同时核对编译器和运行库的版本及[官方兼容保证](https://protobuf.dev/support/cross-version-runtime-guarantee/)，重跑协议黄金字节、全量生成和网络测试。
