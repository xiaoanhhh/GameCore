# 07 三款游戏的扩展实现：同一机制，三种玩法

前几篇讲的是机制。本篇把 Snake、Tank、终极格斗放在一起，按扩展点逐个对照它们**各自写了什么**、**平台替它们做了什么**。三款游戏的玩法差别很大：Snake 是网格离散移动，Tank 是连续坐标射击，格斗有动作状态机和场景平台。它们都通过同一组接口接入，没有修改平台代码。

## 1. 总览

| 扩展点 | Snake | Tank | 终极格斗 |
| --- | --- | --- | --- |
| 规则模块 | `game-snake` | `game-tank` | `game-fight` |
| 输入 `I` | `Direction`（一次转向） | `TankCommand(throttle, turn, fire)`（持续命令） | `FightCommand(move, jump, punch, …)`（持续方向 + 按键脉冲） |
| 快照 `S` | `SnakeSnapshot` | `TankSnapshot` | `FightSnapshot` |
| 会话 | `SnakeGameSession` 包装 `SnakeGame` | `TankSession` 包装 `TankGame` | `FightSession` 自身承载规则 |
| 规则频率 | 20 Hz（格速用整数相位累积） | 60 Hz | 60 Hz |
| 联机工厂 | `SnakeFactory`：`snake/1`，房间 20 Hz | `TankFactory`：`tank/1`，房间 30 Hz（每步 2 个子步） | `FightFactory`：`fight/7`，房间 60 Hz |
| `held()` 持续语义 | 不沿用（转向是一次性的） | 原样沿用 | 只沿用方向/格挡/下，去掉按键脉冲 |
| `select()` 选择权 | P1 选地图 | P1 选地图 | 各自选角色，P1 选地图 |
| 开场演出 | 无 | 无 | 7650 ms，期间规则停在 READY |
| 客户端目录 | 4 个模式 | 4 个模式 | 3 个模式 |
| 在线展示 | `OnlineGameViews.snake` | `OnlineGameViews.tank` | `OnlineGameViews.fight` |

下面按“规则 → 联机 → 客户端”的顺序看代码。

## 2. 规则层：三种 `GameSession` 实现

三款游戏都实现 [GameSession](../game-api/src/main/java/dev/gamecore/api/session/GameSession.java)，并且都使用平台提供的 `SessionInputs` 作为输入队列。区别只在 `tick()` 里怎样使用这些输入。

### Snake：一次转向 + 速度相位

源码：[SnakeGameSession](../game-snake/src/main/java/dev/gamecore/snake/SnakeGameSession.java)

```java
public final class SnakeGameSession implements GameSession<Direction, SnakeSnapshot> {
    public static final int TICKS_PER_SECOND = 20;
    private final SessionInputs<Direction> inputs = new SessionInputs<>();   // 平台的通用输入队列
    private int movementCredit;                                               // 速度相位

    @Override public void tick() {
        if (state() != SessionState.RUNNING) { return; }
        SnakeSnapshot before = game.snapshot();
        for (var input : inputs.drain()) { game.turn(input.player(), input.value()); }
        simulationTick++;
        movementCredit += movementRate();                 // 10~20 格/秒
        if (movementCredit >= TICKS_PER_SECOND) {         // 攒够一格才真正移动
            movementCredit -= TICKS_PER_SECOND; game.tick();
        }
        // 比较前后快照，生成通用事件：ScoreChanged / PlayerDied / MatchEnded
        …
    }
}
```

Snake 的蛇速会从 10 格/秒加速到 20 格/秒，但**规则频率始终是 20 Hz**。加速通过 `movementCredit` 整数相位实现，所以宿主不用知道“蛇变快了”，仍然按固定频率调用 `tick()`。分数和死亡直接使用 `GameEvent` 的通用事件，所以 Snake 不需要改协议事件转换。

### Tank：持续命令 + Bot 走同一入口

源码：[TankSession](../game-tank/src/main/java/dev/gamecore/tank/TankSession.java)

```java
public final class TankSession implements GameSession<TankCommand, TankSnapshot> {
    private final SessionInputs<TankCommand> inputs = new SessionInputs<>();

    @Override public boolean submitInput(PlayerInput<TankCommand> input) {
        if (input.player() > 1) { throw new IllegalArgumentException("Unknown player"); }
        return state() == SessionState.RUNNING
                && !(mode == TankMode.BOT && input.player() == 1)   // Bot 槽位不接受外部输入
                && inputs.offer(input, tickNumber() + 1);
    }
    @Override public void tick() {
        if (state() != SessionState.RUNNING) { return; }
        var before = snapshot();
        for (var input : inputs.drain()) { game.command(input.player(), input.value()); }
        if (bot != null) { game.command(1, bot.command(before, 1)); }  // Bot 只看快照，发同一种命令
        game.tick();
        events = TankEvents.between(before, snapshot());
    }
}
```

`TankSession` 把规则交给 `TankGame`，自己只负责“输入排队 → 交给规则 → 生成事件”。Bot 没有特权，它读快照、产出 `TankCommand`，和玩家走同一条路径。同一份规则因此可以用在本地人机、联机和回放中。

### 终极格斗：动作状态机也装进同一个接口

源码：[FightSession](../game-fight/src/main/java/dev/gamecore/fight/FightSession.java)

```java
public final class FightSession implements GameSession<FightCommand, FightSnapshot> {
    public static final int TICKS_PER_SECOND = 60;

    @Override public void tick() {
        if (state != SessionState.RUNNING) { return; }
        FightCommand[] commands = {FightCommand.NONE, FightCommand.NONE};
        for (var input : inputs.drain()) { commands[input.player()] = input.value(); }
        if (bot != null) { commands[1] = bot.command(snapshot(), 1); }
        tick++;
        // 闪袭判定、按键缓冲、命中停顿（hitstop）、动作状态机、平台碰撞、大招仪式……
        …
    }
    @Override public FightSnapshot snapshot() {
        return new FightSnapshot(tick, state, result, List.of(fighters[0].view(), fighters[1].view()),
                shots…, impacts, hitstop, config.map(), rituals…, teleports);
    }
}
```

格斗是三款游戏里规则最复杂的：动作有起手和硬直，技能有能量门槛和冷却，命中有停顿，地图有单向平台。这些全部在 `tick()` 内部完成，**对外仍然只是 `submitInput` / `tick` / `snapshot` 三个动作**。命中特效需要的 Impact、大招演出需要的 Ritual 放在格斗自己的快照里，没有扩展通用事件。这样通用契约保持稳定，格斗的特殊需求留在格斗内部。

### 规则层的共同点

| 共同点 | 三款游戏的做法 |
| --- | --- |
| 只依赖 `game-api` | 三个 `build.gradle` 都只有 `api project(':game-api')` |
| 输入只是意图 | `Direction`、`TankCommand`、`FightCommand` 都不携带位置、生命或胜负 |
| 输入经平台队列 | 都使用 `SessionInputs`：只收下一 Tick，按序号排序，单 Tick 有上限 |
| 非 RUNNING 不推进 | `tick()` 第一行都检查状态 |
| 快照不可变 | 都是新建的 record，集合做防御性复制 |

## 3. 联机层：三个工厂

每款游戏在 `game-online` 中提供一个 [GameFactory](../game-api/src/main/java/dev/gamecore/api/online/GameFactory.java) 实现。工厂**直接复用规则层的会话**，没有“网络版 Snake / Tank / 格斗”。

### 类型元数据

```java
// SnakeFactory
new GameType("snake", "1", "snake/1", 2, 2, 20, 20);   // 规则 20 Hz，房间 20 Hz
// TankFactory
new GameType("tank",  "1", "tank/1",  2, 2, 60, 30);   // 规则 60 Hz，房间 30 Hz → 每房间步 2 个子步
// FightFactory
new GameType("fight", "1", "fight/7", 2, 2, 60, 60);   // 规则版本随格斗规则迭代到 fight/7
```

房间按 `simulationTps / roomTps` 计算子步数。Tank 降低房间频率不会把规则改成大步长，只是每次房间步推进两个 60 Hz 子步。

### 输入编解码：oneof 防串台

三个工厂的 `decode` 都先检查 `GameInput` 中是不是自己的分支：

```java
// TankFactory.inputs().decode
var b = GameProtocol.GameInput.parseFrom(bytes);
if (!b.hasTank()) { throw new IllegalArgumentException("Wrong game input"); }
// SnakeFactory：if (!b.hasSnake()) …    FightFactory：if (!all.hasFight()) …
```

所以即使两款游戏的字段布局相同，Tank 的房间也不会把 Snake 的输入误读成坦克命令。[RegisteredGameContractTest](../game-online/src/test/java/dev/gamecore/online/RegisteredGameContractTest.java) 对注册表中的游戏两两交叉验证这一点。

### `held()`：断续收包时怎样处理

网络输入不是每个房间步都能准时到达。`held()` 告诉房间“没有新输入时，上一条命令还算不算数”：

```java
// Tank：方向盘和油门是持续状态，原样沿用
@Override public Optional<TankCommand> held(TankCommand input) { return Optional.of(input); }

// Snake：转向是一次性的，不沿用
@Override public Optional<Direction> held(Direction input) { return Optional.empty(); }

// 格斗：方向、格挡、下蹲沿用；出拳、跳跃等按键脉冲去掉，避免一次按键被执行多次
@Override public Optional<FightCommand> held(FightCommand c) {
    return Optional.of(new FightCommand(c.move(), false, false, false, false, c.guard(), false, c.down(), false));
}
```

同一个房间代码（`RoomActor`）对三款游戏都调用 `held()`，差别由游戏自己决定。Tank 和格斗还提供 `neutral()`（空闲命令），持续命令的租约到期时由房间发送，避免掉线后坦克一直开下去。

### `select()`：谁能选什么

```java
// TankFactory：只有 P1（slot 0）能选地图
if (slot != 0 || !choices.keySet().equals(Set.of("map")) || …) throw new IllegalArgumentException("Map ownership");

// FightFactory：P1 选 one 角色和地图，P2 只能选 two 角色
if (… !Set.of(slot == 0 ? "one" : "two", "map").containsAll(choices.keySet())
      || slot != 0 && choices.containsKey("map")) throw new IllegalArgumentException("Selection ownership");
```

客户端不能上传完整配置，只能提交本槽位允许修改的键。白名单由游戏决定，房间只负责调用。

### 登记

源码：[GameRegistry](../game-online/src/main/java/dev/gamecore/online/GameRegistry.java)

```java
public static GameRegistry builtIn() {
    return new GameRegistry(List.of(new TankFactory(), new SnakeFactory(), new FightFactory()));
}
```

服务器的 `RoomHost`、录像的 `ReplayPlayer`、平台的 `LobbyService`、客户端的 `OnlineArenaScreen` 都从这一个列表取工厂。

## 4. 客户端层：目录、本地页面、在线展示

### 目录登记

源码：[client.registry.GameRegistry](../client/src/main/java/dev/gamecore/client/registry/GameRegistry.java)

```java
registry.register(() -> new GameDescriptor("snake", "Snake Arena", "贪吃蛇竞技场", …,
        List.of(new GameMode("classic", …), new GameMode("obstacles", …),
                new GameMode("duo", …), new GameMode("multiplayer", …))));
registry.register(() -> new GameDescriptor("tank", "Tank Arena", "坦克竞技场", …,
        List.of(new GameMode("duel", …), new GameMode("bot", …),
                new GameMode("online", …), new GameMode("multiplayer", …))));
registry.register(() -> new GameDescriptor("fight", "终极格斗", "ULTIMATE FIGHT · 奶蛙 VS 肥嘟嘟", …,
        List.of(new GameMode("bot", …), new GameMode("duel", …), new GameMode("multiplayer", …))));
```

大厅首页、详情、搜索都从 `all()` 生成。模式列表由每款游戏自己声明，所以 Snake 有障碍模式、Tank 有人机三难度、格斗有选人选图，页面代码都不需要知道。

### 本地页面路由

源码：[GameCoreClient.createGameScreen](../client/src/main/java/dev/gamecore/client/GameCoreClient.java)

```java
case "snake" -> new SnakeScreen(this, modeId);
case "tank"  -> "online".equals(modeId) ? new OnlineTankScreen(this) : new TankScreen(this, modeId);
case "fight" -> new FightScreen(this, modeId);
```

每个本地页面都按同一个模式工作：`FixedStepClock` 计算本帧走几步 → 采样键盘 → `submitInput` → `tick` → 把 `snapshot()` 交给只读的 Board 渲染。

### 在线展示

源码：[OnlineGameViews](../client/src/main/java/dev/gamecore/client/network/OnlineGameViews.java)

```java
private static final Map<String, Builder> VIEWS =
        Map.of("snake", OnlineGameViews::snake, "tank", OnlineGameViews::tank, "fight", OnlineGameViews::fight);
```

`OnlineArenaScreen` 负责连接、房间状态、输入世代和快照时间线，对三款游戏完全相同。游戏专属的部分只有“怎样把解码后的快照画出来、怎样采样本游戏的按键”，由各自的 `OnlineGameView` 提供，并且**复用本地页面的同一个 Board**（`SnakeBoard`、`TankBoard`、格斗的场景渲染器）。在线和本地看到的是同一套画面。

## 5. 平台替三款游戏做的事

三款游戏的代码中都**没有**下面这些逻辑，它们由平台统一提供：

| 能力 | 平台代码 | 三款游戏需要做的 |
| --- | --- | --- |
| 固定步长、慢帧保护 | `FixedStepClock`、`SessionLoop` | 无 |
| 输入排序、去重、上限 | `SessionInputs` | 无 |
| 房间单线程调度、分片 | `RoomActor`、`RoomHost` | 无 |
| 输入身份、序号、Tick、世代校验 | `RoomActor` | 只在 `decode` 中校验命令内容 |
| received / executed 确认 | `RoomActor` | 无 |
| 选择、准备、开场、暂停、重开 | `RoomActor` | 提供 `select()`、`openingMillis()` |
| 快照发送与合并 | `AsyncOutbound` | 只提供快照编解码 |
| 录像与重模拟校验 | `ReplayStore`、`ReplayPlayer` | 无 |
| 账户、建房、票据、结算 | `platform-service` | 无 |
