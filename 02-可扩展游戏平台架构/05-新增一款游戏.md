# 05 实战：新增一款游戏

以一款**尚未实现**的双人 Pong 为例说明接入步骤。文中的 `game-pong`、`PongSession` 等名称仅为示意，仓库中不存在这些文件。

## 1. 改动清单总览

| 阶段 | 新写 | 登记（每处一行或一个分支） | 复用，不改 |
| --- | --- | --- | --- |
| A 规则 | `game-pong` 模块：`PongCommand`、`PongSnapshot`、`PongSession`、规则测试 | `settings.gradle` 加 `include 'game-pong'` | `GameSession`、`PlayerInput`、`SessionInputs`、`SessionLoop`、`GameEvent` |
| B 本地客户端 | `PongBoard`、`PongControls`、`PongScreen` | client `build.gradle` 依赖；客户端目录 `register`；`createGameScreen` 加 `case` | 大厅、设置、主题、`FixedStepClock`、`UiScreen` |
| C 联机适配 | `PongFactory`、`PongSnapshotCodec` | `games.proto` 两个 oneof 各加一支；game-online `build.gradle` 依赖；在线 `GameRegistry.builtIn()` 加一项 | `GameInstance`、`RoomActor`、`RoomHost`、Netty、`AsyncOutbound`、录像 |
| D 在线展示 | `OnlineGameView` 实现 | `OnlineGameViews.VIEWS` 加一项 | `OnlineArenaScreen`、`RemoteArenaSession`、快照时间线 |
| E 平台 | 无 | 无 | 账户、建房、票据、结算、战绩 |

阶段 A 完成后即可单独测试和本地游玩，B 之后可上大厅，C、D 之后可联机，E 自动可用。按“先做出可运行的垂直切片”的开发原则，建议 A → B 先跑通，再做 C → D。

## 2. 分步说明

### A. 规则模块（纯 Java）

```groovy
// game-pong/build.gradle —— 只依赖契约，编译期隔离图形与网络
dependencies { api project(':game-api') }
```

```java
public record PongCommand(int paddle) {               // -1 上 / 0 停 / 1 下：只有意图
    public PongCommand { if (paddle < -1 || paddle > 1) throw new IllegalArgumentException("paddle"); }
    public static final PongCommand IDLE = new PongCommand(0);
}
public record PongSnapshot(long tick, SessionState state, double ballX, double ballY,
                           List<Double> paddles, List<Integer> scores, String result) {
    public PongSnapshot { paddles = List.copyOf(paddles); scores = List.copyOf(scores); }  // 防御性复制
}
public final class PongSession implements GameSession<PongCommand, PongSnapshot> {
    private final SessionInputs<PongCommand> inputs = …;   // 复用平台输入队列
    // start/pause/resume/submitInput/tick/snapshot/events …
}
```

逐项对照 [02 第 8 节检查清单](02-规则内核契约.md#8-新游戏实现-gamesession-的检查清单)。计分变化发 `GameEvent.ScoreChanged`，终局发 `MatchEnded`——使用通用事件可免去协议事件转换的改动。

### B. 本地客户端

1. `client/build.gradle` 增加 `api project(':game-pong')`。
2. [client.registry.GameRegistry.builtIn()](../client/src/main/java/dev/gamecore/client/registry/GameRegistry.java) 增加 `registry.register(() -> new GameDescriptor("pong", …, List.of(new GameMode("duel", …), new GameMode("multiplayer", …))))`。
3. 新包 `client/.../pong/`：`PongBoard`（只读快照渲染）、`PongControls`（键位采样）。
4. `PongScreen extends UiScreen`：参照 [TankScreen](../client/src/main/java/dev/gamecore/client/screen/TankScreen.java) 的 `restart()/render()/refresh()` 骨架。
5. [GameCoreClient.createGameScreen](../client/src/main/java/dev/gamecore/client/GameCoreClient.java) 增加 `case "pong" -> new PongScreen(this, modeId);`。

### C. 联机适配

1. [games.proto](../protocol/src/main/proto/games.proto)：

   ```protobuf
   message GameInput    { oneof payload { TankInput tank = 1; SnakeInput snake = 2; FightInput fight = 3; PongInput pong = 4; } }
   message GameSnapshot { oneof payload { TankView  tank = 1; SnakeView  snake = 2; FightView  fight = 3; PongView  pong = 4; } }
   message PongInput { sint32 paddle = 1; }
   message PongView  { … }
   ```

   只追加新字段号，不改已有编号，旧客户端解析不受影响。

2. `game-online/build.gradle` 增加 `api project(':game-pong')`，新建 `online/pong/PongFactory`，参照 [TankFactory](../game-online/src/main/java/dev/gamecore/online/tank/TankFactory.java)：

   ```java
   public final class PongFactory implements GameFactory<PongCommand, PongSnapshot> {
       private final GameType type = new GameType("pong", "1", "pong/1", 2, 2, 60, 30);
       @Override public GameType type() { return type; }
       @Override public GameRuleConfig defaults() { return new GameRuleConfig(2, 30, Map.of("arena", "classic")); }
       @Override public void validate(GameRuleConfig c) { c.require(type); /* 白名单校验 options */ }
       @Override public GameSessionFactory<PongCommand, PongSnapshot> sessions() { return (c, seed) -> { validate(c); return new PongSession(seed); }; }
       @Override public GameInputCodec<PongCommand> inputs() { … decode 时检查 hasPong()，neutral() 返回 IDLE … }
       @Override public GameSnapshotCodec<PongSnapshot> snapshots() { return new PongSnapshotCodec(); }
       @Override public PongCommand bot(PongSnapshot s, int slot, long step, boolean active) { … }
   }
   ```

3. [在线 GameRegistry.builtIn()](../game-online/src/main/java/dev/gamecore/online/GameRegistry.java) 的列表中加入 `new PongFactory()`。此后 RoomHost 默认房间、ReplayPlayer、LobbyService 和 OnlineArenaScreen 都能通过 `require("pong")` 取到它。

### D. 在线展示

在 [OnlineGameViews](../client/src/main/java/dev/gamecore/client/network/OnlineGameViews.java) 中实现 `pong(...)` 构建方法返回 `OnlineGameView`（复用 `PongBoard`），并把 `"pong", OnlineGameViews::pong` 加入 `VIEWS`。

### E. 平台

无需代码修改。若部署配置需要单独调整 Pong 的房间频率，见 [06](06-扩展边界与演进方向.md) 中 `DeploymentConfig` 一项。

## 3. 不应该出现的改动

如果接入过程中发现自己在改下列位置，说明扩展方向错了：

- 在 `RoomActor`、Netty 处理器、`LobbyService` 中写 `if ("pong".equals(gameId))`。
- 在 Board 或特效里计算得分、碰撞、胜负。
- 让规则模块依赖 libGDX、Netty、Protobuf 或 Spring。
- 修改 Tank/Snake/Fight 的规则以“适配”新游戏。
- 修改已有 proto 字段编号。

## 4. 用测试证明接入成功

| 层 | 测试 | 参照 |
| --- | --- | --- |
| 规则契约 | 输入序号决定顺序、持续命令与 IDLE、暂停清理、终局事件只发一次 | [TankSessionContractTest](../game-tank/src/test/java/dev/gamecore/tank/TankSessionContractTest.java) |
| 确定性与编解码 | 同 seed 两个 `GameInstance` 逐步结果一致；快照编码往返相等；错误游戏负载被拒绝 | [AdapterTest](../game-online/src/test/java/dev/gamecore/online/AdapterTest.java) 的 `roundtrip`、`codecsRejectWrongGameAndIllegalValues` |
| 注册表 | `GameRegistry.builtIn().all()` 数量更新；重复 ID 被拒绝 | `AdapterTest.registryAndVersions`（现断言为 3，需同步更新） |
| 房间 | 输入确认、单写入者、选择白名单 | [RoomActorTest](../game-server/src/test/java/dev/gamecore/server/multigame/RoomActorTest.java)、[InteractiveRoomTest](../game-server/src/test/java/dev/gamecore/server/multigame/InteractiveRoomTest.java) |
